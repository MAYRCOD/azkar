# Тексты приложения

Здесь лежат все тексты: азкары, аяты дня и дуа. Код приложения (`src/app.html`)
их не содержит — сборка `tools/build.py` вставляет эти файлы в приложение.

Зачем отдельно: тексты правятся чаще всего, и в одном файле с кодом их легко
задеть случайно. А ещё эти же файлы потом сможет читать приложение на Swift —
тексты останутся в одном месте и не разойдутся.

Формат — JSON. Главные правила: строки в двойных кавычках `"…"`, перенос строки
внутри текста — `\n`, кавычка внутри текста — `\"`, после последнего элемента
списка запятой НЕТ. Если ошиблись — `python3 tools/build.py` скажет, в какой строке.

## azkar.json — утренние и вечерние азкары

```
{
  "full_order": { "morning": [id, …], "evening": [id, …] },
  "items": [ азкар, … ]
}
```

Азкар:
- `id` — уникальное имя (`m-…` утро, `e-…` вечер, `f-…`/`fm-…`/`fe-…` — только в «Полных»).
  По `id` хранится прогресс счётчика у людей, поэтому у существующих азкаров его не менять.
- `when` — `["morning"]` или `["evening"]`; `times` — сколько раз читать.
- `name`, `ar`, `ru`, `tr`, `src` — название, арабский, перевод, транскрипция, источник.
- `full: true` — только в «Полных».

«Основные» — азкары без `full` в порядке списка `items`.
«Полные» — порядок из `full_order` (по видео Майрбека, 11.10.2026).
Один и тот же азкар в обоих наборах — одна запись (тот же текст и прогресс).
Исключение: «Ля иляха илля-Ллах» — в полных `f-14` (100 раз), в основных 10 раз.
Вечер: `e-bika` и `e-alim` в видео нет, но они в «Основных» — стоят там же, где в утренних.
`f-19`…`f-21` — те же записи, что утром; прогресс у вечера свой.

Порядок в `items` (было комментариями в коде): утренние основные → только «Полные»
утренние из видео (перевод, транскрипция, повторы дословно) → «Полные» по книге
«Крепость мусульманина» → то же для вечерних.

## ayat.json — аят дня

Список `{ "ref": "аль-Бакара, 152", "ar": …, "ru": … }`. Каждый день — следующий по кругу
(по местной дате). Арабский — text_uthmani с quran.com, перевод — Э. Кулиев
(quran.com, перевод №45), сверены символ в символ. Перед добавлением аята проверить,
что все символы есть в шрифте Hafs, и посмотреть карточку в приложении.
Новые аяты добавлять в конец, иначе у всех «сдвинется» аят дня.

## dua.json — раздел «Дуа»

```
[ группа { "title", "cats": [ тема { "id", "name", "tile" (цвет плитки), "icon" (имя значка из ICONS в app.html),
                                      "items": [ дуа, … ] } ] } ]
```

Дуа: `id` (по нему хранится «Избранное» — не менять), `title`, `how` (пояснение),
`ar`, `ru`, `tr`, `src`; `adds` — источники дополненных частей `{{…}}`
(строка-источник или `{ "note": "…" }`).

Ссылки вместо текста (чтобы суры и аяты не хранились дважды):
- `"from": ["m-ikhlas", "m-falaq", "m-nas"]` — взять `ar`/`ru`/`tr` из азкаров с этими `id`
  и склеить; `"sep": "\n"` — склеивать арабский и перевод с новой строки (без него — пробел).
- `"from_ayah": "аль-Хадид, 3"` — взять `ar` и `ru` из аята дня с этим `ref`.
Если в дуа уже есть своё поле (например, своя `tr`), оно остаётся.

## quran/ — раздел «Коран» (файлы готовит tools/make_quran.py, руками не править)

Источники лежат в `src/quran-src/`:
- `hafsData_v18.json` — текст Мединского мусхафа от Комплекса короля Фахда (KFGQPC), версия 18:
  текст аята (номер в конце — шрифт рисует его в кружке). Страницы и джузы оттуда НЕ берём:
  джузы там поделены не по мединскому мусхафу (3:92 — в 4-м джузе, 9:93 — в 10-м), а у 56 аятов
  на стыке страниц номер страницы сдвинут на одну.
  Текст НЕ меняем ни на символ: таково условие Комплекса, и под него сделан шрифт
  `src/fonts/kfgqpc-hafs-v18.ttf` (той же версии). Взято из github.com/thetruetruth/quran-data-kfgqpc
  (копия данных qurancomplex.gov.sa); буквы сверены с quran.com.
- `kuliev.json` — перевод смыслов Э. Кулиева по аятам: api.quran.com, перевод №45 (со знаками
  препинания; в копиях tanzil их в конце аятов нет). Скачан во встроенном браузере на компьютере
  Майрбека и перенесён с проверкой контрольной суммой. Арабский текст 30-го джуза сверен с
  quran.com (text_qpc_hafs) — все 564 аята совпали символ в символ.
  Суры 1–77 (20.10.2026): перевод получен тем же способом, большие ответы браузера приходят файлом
  без перепечатки; проверено по частям (23 части) и всем файлом по контрольной сумме FNV-1a.
  Арабский всех 6236 аятов сверен с quran.com: буквы совпали везде; единственное отличие —
  2:72, перед номером аята у KFGQPC неразрывный пробел, у quran.com обычный (оставлен KFGQPC).
- `pages-tanzil.json` — джуз для каждого аята (разметка Tanzil, через github.com/fawazahmed0/quran-api).
  Страницы в нём — по изданию 1421 г.; с 25.10.2026 страницы берём из раскладки 1441 (см. «Мусхаф» ниже).
  21.10.2026 сверено с quran.com: совпали все 6236 аятов.
  Данные quran.com в проекте не храним (их условия ограничивают встраивание в приложение).
  Начала 30 джузов записаны в `tools/make_quran.py` (JUZ_STARTS) — сборка сверяет с ними;
  4-й (3:93) и 11-й (9:93, стр. 201) джуз проверил Майрбек.
- `meanings-ru.json` — значения названий сур по-русски (quran.com).
- `names-ru.json` — русские названия сур; `chapters.json` — аяты с земным поклоном (мекканская/мединская там тоже есть, но в приложении не показываются).

`python3 tools/make_quran.py` собирает из них `src/data/quran/index.json` (список сур, басмала, начала джузов)
и по файлу на суру (`112.json` …). В приложение попадают только суры, для которых есть перевод и название.
Сборка `tools/build.py` кладёт их в папку `quran/` рядом с index.html: приложение берёт файл суры,
только когда её открыли.

## Режим «Мусхаф» — все 604 страницы (ветка mushaf2)

- Раскладка — мединский мусхаф издания 1441 г. («KFGQPC V4 layout (1441H print)», qul.tarteel.ai/resources/mushaf-layout/19):
  `src/quran-src/mushaf/layout-v4.json`. В раскладке отмечено, какие строки стоят по центру.
- Шрифты страниц QCF V4: `src/mushaf-fonts/pN.woff2` (verses.quran.foundation/fonts/quran/hafs/v4/colrv1/woff2/pN.woff2),
  файлы не меняем. Внутри COLR v0 (понимает iPhone), палитры: №0 таджвид, №3 чёрный текст, №4 белый.
  Шрифт V4 подходит только к раскладке 1441 (с переносами 1421 строки разной ширины).
- Скачаны 25.10.2026 на сервере GitHub Actions (`tools/fetch_mushaf.py`, запуск — `.github/workflows/fetch-mushaf.yml`,
  срабатывает от пуша в ветку `mushaf-fetch`); SHA-256 — в `src/quran-src/mushaf/fetch-manifest.json`. Сверено с тем,
  что раньше скачано через браузер Майрбека (стр. 1–2, 582–604): раскладка совпала полностью, шрифты — кроме стр. 1–2
  (на сайте новая версия от 06.2025, у браузера была старая из кэша).
- `tools/make_mushaf.py` → `src/data/quran/mushaf/N.json` (604 страницы) и `index.json` (для каждой страницы: s/a — первый аят,
  который на ней начинается, es/ea — последний). Проверки: 15 строк, все глифы есть в шрифте страницы, аяты 1:1…114:6
  подряд, 114 заголовков, 112 басмал.
- Сборка (`tools/build.py`) кладёт в `quran/mushaf/` блоки по 20 страниц: `pages-K.json` (страницы + поле "_f": где чей шрифт)
  и `fonts-K.bin` (шрифты этих страниц подряд). 31+31 файл вместо 1208 — меньше запросов, и всё помещается в предпросмотр.
- Номера страниц в текстовом режиме теперь тоже по изданию 1441 (`tools/make_quran.py` берёт их из раскладки): изменились
  у 56 аятов, не больше чем на одну страницу — ровно те 56, где данные KFGQPC расходились с Tanzil. Начала джузов те же.
- `src/fonts/surah-header.woff2` — заголовки сур, QCF Surah Header (static-cdn.tarteel.ai/qul/fonts/surah-names/surah-header/
  QCF_SurahHeader_COLOR-Regular.woff2, qul.tarteel.ai/resources/font/458), рамка с названием — один знак (M_HDR в app.html).
  Лицензия на QUL не указана — уточнить до App Store.
- Басмала — SVG с quran.com (M_BSML в app.html).
- На экране: ширина строки W, 15 строк с шагом W/9.3 (пропорции книги), шрифт страницы — по её самой длинной полной строке.
  Рисуются только текущая страница и соседние, шрифты и блоки дальних выгружаются (иначе телефон закрывает вкладку).
